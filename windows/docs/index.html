이 프로그램은 서버 PC, 저장소, SD EEPROM 준비, 부팅 서비스 점검을 버튼으로 처리하게 만든 도구입니다.

현재: 준비 중

서버 PC

유선 이더넷을 10.73.0.10으로 두고 Pi 부팅망을 담당합니다.

저장소

D:\tftp에는 부팅 파일, D:\rootfs에는 Pi별 Linux 파일시스템을 둡니다.

Pi 4

처음 한 번 EEPROM을 네트워크 부팅 가능 상태로 바꿔야 합니다.

지금 바로 부팅 완료 상태는 아닙니다. PC/IP/폴더와 DHCP/TFTP 흐름은 확인됐고, 현재 핵심 blocker는 첫 RPi4의 D:\rootfs\d80c0b88를 실제 Linux rootfs로 채우는 일입니다.

용어 정리

haneWIN은 내가 만든 이름이 아니라 Windows용 서버 제품군입니다

Windows에서 Raspberry Pi 네트워크 부팅에 필요한 DHCP, TFTP, NFS 역할을 제공하는 후보 도구입니다.

제품명
DHCP
Pi에게 IP와 부팅 서버 정보를 알려줍니다.
TFTP
Pi가 전원을 켤 때 필요한 커널, dtb, firmware 파일을 전달합니다.
NFS
Pi가 Linux rootfs를 네트워크 드라이브처럼 마운트하게 합니다.
haneWIN은 빠른 검증용 provider입니다. 미등록 상태에서는 30일 평가판으로 동작하므로 장기 운영 기본값으로 안내하지 않습니다. 운영용 provider는 오픈소스/내장 조합으로 준비 중입니다.

공식 haneWIN 사이트에도 Raspberry Pi를 Windows에서 네트워크 부팅하는 가이드와 DHCP/TFTP/NFS 제품 문서가 있습니다.

장기 운영 방향

Windows판도 DHCP, TFTP, NFS provider를 선택하게 만듭니다

Linux판의 dnsmasq/TFTP/NFS 역할을 Windows에서 어떤 조합으로 실행할지 분리합니다.

provider

무료 Lite provider

내장 DHCP/TFTP 서버와 WinNFSd로 haneWIN 없이 먼저 테스트합니다.

haneWIN

빠른 비교용입니다. 미등록 30일 평가판이므로 운영 기본값으로 쓰지 않습니다.

오픈소스 스택

Open DHCP Server, Tftpd64, WinNFSd 조합은 추가 provider 후보로 유지합니다.

Windows 내장/서버

Windows Server DHCP/NFS 또는 내장 기능을 쓰는 환경은 별도 운영 provider로 분리합니다.

지금 테스트는 무료 Lite provider를 먼저 씁니다. haneWIN은 30일 평가판이므로 비교/검증용으로만 유지합니다. 자세한 표는 docs\windows-service-providers.md에 있습니다.

버튼 순서

처음에는 이 순서대로 누르면 됩니다

중간에 실패가 나오면 다음 단계로 넘어가지 말고 해당 항목을 먼저 해결합니다.

7단계
1
상태 확인
현재 PC, D: 저장소, S: SD카드, 서비스 포트를 읽기 전용으로 확인합니다.
2
서버 PC 자동 준비
D: 폴더 구조와 유선 IP 10.73.0.10을 맞춥니다.
3
무료 부팅 서비스 시작
내장 DHCP/TFTP 서버와 WinNFSd를 시작합니다. haneWIN 없이 먼저 확인합니다.
4
SD카드에 EEPROM 쓰기
Pi 4가 네트워크 부팅을 시도하도록 EEPROM 업데이트 SD를 만듭니다.
5
첫 Pi 부팅파일 복사
Raspberry Pi OS boot 파티션의 start4.elf 파일들을 D:\tftp\<serial>로 가져옵니다.
6
첫 Pi rootfs 복제
D:\rootfs\<serial>에 실제 Linux rootfs를 채웁니다. Windows 탐색기 복사는 피합니다.
7
전체 상태 다시 확인
서비스 포트와 TFTP/rootfs 상태를 다시 확인합니다.

점검 결과 해석

현재 정상인 것과 아직 필요한 것

상태 확인 로그의 `[정상]`, `[주의]`, `[필요]`를 이렇게 읽으면 됩니다.

68 / 100
정상
D:는 rpi 라벨의 NTFS 고정 저장소입니다.
정상
유선 이더넷은 10.73.0.10/24, 공유기 10.73.0.1 ping도 성공합니다.
정상
D:\tftp, D:\rootfs, D:\iscsi, D:\downloads 폴더가 있습니다.
정상
테스트 RPi4는 DHCP/TFTP로 커널까지 받았습니다. MAC은 88:a2:9e:4f:a9:b1, serial은 d80c0b88입니다.
정상
D:\tftp\d80c0b88에는 RPi4 부팅 파일이 준비되어 있습니다.
필요
D:\rootfs\d80c0b88에 실제 Linux rootfs를 채워야 합니다. 지금 커널 panic의 핵심 원인입니다.

첫 장비 온보딩

첫 Pi 한 대를 기준 장비로 만들어야 합니다

첫 Pi가 성공하면 그 구조를 복제해서 다음 Pi들을 등록하는 방식으로 갑니다.

다음 작업
1
S: SD카드에 EEPROM 이미지를 씁니다.
2
Pi 4를 그 SD카드로 한 번 부팅해서 EEPROM을 업데이트합니다.
3
첫 Pi의 serial과 MAC을 확인합니다.
4
첫 Pi 부팅파일 복사 버튼으로 Raspberry Pi OS boot partition 파일을 채웁니다. EEPROM SD는 이 용도가 아닙니다.
5
D:\rootfs\<serial>에 Linux rootfs를 복제합니다. Windows 탐색기 복사는 권한이 깨질 수 있어 피합니다.

체크

DHCP UDP 67 필요

Pi에게 IP와 부팅 서버 정보를 줄 DHCP 서버가 아직 실행되지 않았다는 뜻입니다.

TFTP UDP 69 필요

Pi가 부팅 파일을 받아갈 TFTP 서버가 아직 실행되지 않았다는 뜻입니다.

NFS TCP 2049 필요

Pi가 rootfs를 마운트할 NFS 서버가 아직 실행되지 않았다는 뜻입니다.

가장 위험한 작업은 SD 쓰기입니다. 확인창에서 대상이 반드시 S: SD카드인지 확인하세요. D:는 서버 저장소라 지우면 안 됩니다.
