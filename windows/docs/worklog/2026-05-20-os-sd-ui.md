# 2026-05-20 OS SD UI Restructure

## Trigger

The operator stopped the EEPROM-only path and asked to restructure the UI because the next practical step is to write a Raspberry Pi OS SD, boot the target Pi, confirm serial/MAC, and handle EEPROM/network boot settings from the OS.

The previously specified OS version was found in the worklog:

```text
Raspberry Pi OS Lite 64-bit Trixie
2026-04-21-raspios-trixie-arm64-lite.img
```

## Storage Cleanup

All remaining `D:\downloads` contents were moved into the project-local cache:

```text
windows\cache\downloads
```

`D:\downloads` is now empty. This keeps reproducible images and helper artifacts inside the active project tree instead of scattered on `D:\`.

## Implementation

- GUI action `prepare-sd` now appears as `RPi4 OS SD 작성`.
- The physical disk selector is reused for SD image writes and no longer says EEPROM.
- `rpi-netboot-manager.ps1 -Task prepare-sd` now maps to `Invoke-PrepareRpi4OsSd`.
- `rpi-sd-card.ps1` gained:
  - `download-rpios-lite-trixie`
  - `prepare-rpios-lite-trixie`
- The OS image is pinned to:

```text
windows\cache\downloads\2026-04-21-raspios-trixie-arm64-lite.img
```

EEPROM image writing remains available as a CLI fallback:

```powershell
.\tools\rpi-sd-card.ps1 prepare-eeprom-network -Model pi4 -DiskNumber <번호> -IUnderstand
```
